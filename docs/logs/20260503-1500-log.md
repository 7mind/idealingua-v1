## Original user request

> This is an old IDL/DML compiler which I created many years ago. It has a fatal issue: no proper intermediate representation and no proper typer — all the computations happen ad-hoc in each target backend. Also, the stub typer I've implemented is insanely slow. I did my homework since, that ( https://github.com/7mind/baboon ) project implements proper typer and supersedes idealingua but there are production systems which depend on this legacy project AND its wire format, so I need to maintain this old compiler. Good news: golang and protobuf backends can be erased, no one uses them. So, what I want to do:
> 1. Review my approaches to small and efficient typers which I implemented in Baboon (typer is a DAG transformation consisting of many micro-phases).
> 2. Devise a detailed plan on how we can modernise this old compiler: implement proper typer, implement modern backends, get rid of old backends (or rewrite them if feasible).
> 3. Devise a plan how we can maintain strong backward compatibility (byte to byte) and reliably test that.

Deliverable was **plan documents only**, not implementation. Worked in `/review-loop` per the user's directive.

## What surprised us

- **Byte-for-byte is more load-bearing than the meta-plan signalled.** PR-03 round 1 caught that the harness as initially designed would have accepted field-order regressions. Fixed by demoting canonicalization to a sanity check.
- **The legacy compiler's "delete Go" footprint was wider than the meta-plan's inventory.** PR-02 round 1 found four extra implicit codec defs in `Codecs.scala`, an entire `CredentialsReader.scala`, and a hard-coded literal in `CommandlineIDLCompiler.scala:283` — all of which would have caused IMPL-8 to fail to compile under the original §5.
- **C# emits `???` for `TBLOB`** (`JsonNetExtension.scala:188`). There is no current C# baseline for TBLOB, so PR-02 cannot ship a TBLOB change. PR-03 §11 Q12 captures this as an open question.
- **`Array[Byte]` is a footgun in Scala.** PR-02 §4 Fingerprint type changed from `Array[Byte]` (reference equality) to `IArray[Byte]` (structural equality) so the frozen-after-assembly invariant works correctly.
- **`Domain.userTypes` projection** is now part of the new IR. The legacy `ctx.typespace(a)` call sites map to `ctx.domain.userTypes(a)` rather than `ctx.domain.members(a)` because `members` returns `Member` (sealed trait), not `TypeDef`.
